# ADR-003: Whitelist + привязка к 1С-пользователю

## Статус
Accepted

## Контекст
Telegram — внешний канал. Бот работает с финансовыми данными компании. Нужно контролировать доступ: кто может задавать вопросы и к чьим данным. Связано с **TM-03** (Elevation of Privilege / доступ к чужим данным) и **TM-06** (Sensitive Information Disclosure). Покрывает **NFR-SEC-001**.

## Решение
Whitelist Telegram ID. Каждый ID привязан к пользователю 1С (для аудита и разграничения данных). Неавторизованные — отклоняются с сообщением. Привязка к 1С-пользователю позволяет: (1) в аудите писать реального пользователя, (2) разграничивать данные (если в 1С несколько организаций/участков), (3) отзывать доступ через 1С.

## Последствия

**Плюсы:**
- Защита от утечки данных (TM-03, TM-06).
- Аудит привязан к конкретному пользователю 1С.
- Возможность разграничения данных между пользователями.
- Отзыв доступа через 1С (единая точка управления).

**Минусы:**
- Ручное управление whitelist (добавление/удаление ID).
- Требуется синхронизация Telegram ID ↔ 1С-пользователь (справочник или константа).
- При смене Telegram-аккаунта — ручное обновление.

**Риски:**
- Подмена Telegram ID → **Митигация:** whitelist + логирование `security.blocked` (T-206).
- Утечка данных через ответ → **Митигация:** фильтрация ответа по правам 1С-пользователя (T-206).

**Влияние на наблюдаемость:**
- Добавлен сигнал `telegram.messages.total` с `status` (allowed/blocked) (OBS-C-01).
- Добавлен лог `security.blocked` с `reason`, `user_id` (hashed), `trace_id` (OBS-C-01, OBS-C-04).
- **Влияние на OBS-C-01…06:** OBS-C-01 (покрытие FR-005), OBS-C-04 (hashed user_id в логах).

## Альтернативы
| Альтернатива | Отклонена | Причина |
|---|---|---|
| Открытый бот для всех | Да | Утечка финансовых данных |
| Whitelist без привязки к 1С | Да | Нет разграничения данных и аудита по 1С-пользователю |
| OAuth через 1С | Да | Избыточно для MVP; усложняет UX в Telegram |
