# ADR-001: Выбор российской LLM

## Статус
Accepted

## Контекст
Требование: LLM должна быть российской (NFR-006). Нужна модель для двух задач: (1) классификация интентов (function calling), (2) синтез ответа с цитированием. Связано с **TM-10** (Spoofing / подмена провайдера) и **NFR-006**. Дополнительно: **NFR-OBS-001** (llm.request.duration) и **OBS-C-02** (traceparent в LLM-вызовах).

Кандидаты:
- **GigaChat 3.5 Reasoning** (Сбер, 432 млрд MoE, API через Cloud.ru) — наивысший балл среди российских моделей в MERA v2 (0,279), режим рассуждений, подходит для финансов/права.
- **RusMind Сокол 4.7** (DICPlay, 8,9 млрд, открытые веса GGUF) — второе место среди российских моделей в MERA v2, работает офлайн, поддерживает вызов инструментов.
- **YandexGPT 5.1 Pro** (Яндекс) — только API, нет локального развёртывания.
- **Meno-Lite-0.1** (НГУ, 7,6 млрд, Apache 2.0) — специально оптимизирована для RAG.

## Решение
**Гибридная стратегия:**
- **Синтез ответа + классификация:** GigaChat 3.5 Reasoning через API Cloud.ru — первый выбор (качество + режим рассуждений).
- **RAG-эмбеддинги:** Meno-Lite-0.1 — специализация на RAG, открытая лицензия.
- **Fallback:** RusMind Сокол 4.7 (Ollama/llama.cpp) — если API недоступен или требуется полная локальность.

**Способ доступа к Meno-Lite-0.1:**
- **Первичный:** HuggingFace (`ngs-meno/meno-lite-0.1`) через `sentence-transformers` (локальный чекпоинт).
- **Альтернатива:** локальный GGUF-файл через `llama.cpp` / `Ollama` (если API недоступен).
- **Параметры RAG (из design.md):** `k=5`, `chunk_size=500` токенов, `chunk_overlap=50`.

**Защита от TM-10:** конфигурация LLM-провайдера валидируется при старте — допускаются только `{GigaChat, Meno-Lite, RusMind}`; иные провайдеры отклоняются (тест TC-026).

## Последствия

**Плюсы:**
- Все компоненты — российские разработки (NFR-006).
- GigaChat Reasoning — лучший балл среди российских моделей.
- Meno-Lite — специализация на RAG, Apache 2.0.
- RusMind — fallback для offline/приватности.
- Защита от подмены провайдера (TM-10).

**Минусы:**
- GigaChat через API → финансовые данные уходят в Cloud.ru (инфраструктура РФ, но внешняя).
- RusMind 8,9B слабее GigaChat 432B → fallback даёт менее качественные ответы.
- Два провайдера (GigaChat + RusMind) → усложнение кода и тестирования.

**Риски:**
- GigaChat API недоступен → **Митигация:** fallback на RusMind (T-203).
- Конфигурация подменена на не-российский провайдер → **Митигация:** валидация при старте (T-307).

**Влияние на наблюдаемость:**
- Добавлен сигнал `llm.request.duration` (metric) с атрибутами `llm.model`, `llm.provider` (OBS-C-01, NFR-OBS-001).
- Добавлен span `llm.synthesize` с `trace_id`, `llm.model`, `tokens.in/out` (OBS-C-02, NFR-OBS-002).
- **Влияние на OBS-C-01…06:** OBS-C-01 (покрытие сигналов для FR-004), OBS-C-02 (traceparent в LLM-вызовах), OBS-C-03 (SLO latency привязан к `llm.request.duration`).

## Альтернативы
| Альтернатива | Отклонена | Причина |
|---|---|---|
| YandexGPT 5.1 Pro (только API) | Да | Нет локального развёртывания; не подходит для fallback |
| Только GigaChat (без fallback) | Да | Единая точка отказа; нет offline-режима |
| Только RusMind (без GigaChat) | Да | Ниже качество по бенчмаркам |
| Зарубежная LLM (GPT-4, Claude) | Да | Нарушает NFR-006 |
