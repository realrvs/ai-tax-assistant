# ADR-002: RAG с обязательным цитированием и векторная БД Chroma

## Статус
Accepted

## Контекст
LLM может галлюцинировать статьи НК РФ — критично для налоговой тематики (штрафы за неверные ответы). Нужна защита от misinformation (**TM-07**) и insecure output (**TM-05**). Связано с **NFR-SEC-003** (обязательное цитирование), **NFR-003** (≥ 95% ответов с корректной ссылкой), **NFR-OBS-001** (rag.search.duration), **OBS-C-02** (traceparent в RAG-вызовах).

Дополнительно: выбор векторной БД для хранения эмбеддингов НК РФ и формат цитирования.

## Решение
**RAG с обязательным цитированием:**
- RAG-сервис возвращает top-k статей с номерами и текстом.
- Синтезатор **обязан** включить ссылку на статью НК РФ в ответ.
- Ответ без ссылки отклоняется → «Не удалось подтвердить ответ источником».
- Валидация цитаты: номер статьи из ответа должен присутствовать в результатах RAG-поиска.

**Формат цитирования (TM-07):** номер статьи + пункт + краткая цитата (1–3 предложения). Пример: «Согласно ст. 164 п. 1 НК РФ, ставка НДС составляет 20%». Полный текст — по команде «подробнее».

**Векторная БД:** **Chroma** для MVP. Обоснование: простой старт (in-memory + persistent), Python-native, не требует отдельного сервера, достаточно для корпуса НК РФ (несколько тысяч чанков). При росте — миграция на Qdrant.

## Последствия

**Плюсы:**
- 100% ответов содержат источник (NFR-SEC-003).
- Снижение галлюцинаций (TM-07).
- Прозрачность для пользователя — можно проверить статью.
- Chroma — быстрый старт, Python-native, persistent mode.

**Минусы:**
- Усложнение синтезатора (пост-валидация цитат).
- Возможны случаи «не удалось подтвердить источником» → нужен fallback (уточняющий вопрос).
- Зависимость от качества RAG-поиска: если top-k не содержит нужную статью, ответ будет отклонён.
- Chroma не production-grade при больших объёмах (> 1M векторов) → миграция на Qdrant при росте.

**Риски:**
- RAG не находит нужную статью → **Митигация:** уточняющий вопрос + расширение top-k при низком confidence (T-104).
- Chroma теряет данные при перезапуске → **Митигация:** persistent mode + бэкап индекса (T-103).

**Влияние на наблюдаемость:**
- Добавлен сигнал `rag.search.duration` (metric) с `top_k`, `result.count` (OBS-C-01, NFR-OBS-001).
- Добавлен span `rag.search` с `query.length`, `top_k`, `result.count`, `trace_id` (OBS-C-02, NFR-OBS-002).
- Добавлен сигнал `answer.citation.present.total` (metric) с `present`, `tax.type` (OBS-C-01, OBS-C-03).
- **Влияние на OBS-C-01…06:** OBS-C-01 (покрытие FR-001, FR-004), OBS-C-02 (traceparent в RAG), OBS-C-03 (SLO citation presence).

## Альтернативы
| Альтернатива | Отклонена | Причина |
|---|---|---|
| Без обязательного цитирования | Да | Не защищает от TM-07 |
| Только номер статьи (без пункта) | Да | Ниже точность валидации |
| Полный текст пункта в каждом ответе | Да | Слишком длинно для Telegram |
| FAISS вместо Chroma | Да | Требует больше конфигурации, менее Python-native |
| Qdrant вместо Chroma | Да | Избыточен для MVP (несколько тысяч чанков) |
