## Why

Бухгалтеры и руководители малого/среднего бизнеса тратят до 30% рабочего времени на поиск ответов по налогам: листают НК РФ, сверяют с фактическими данными в 1С, готовят ответы на запросы ФНС. Ответы в интернете противоречивы, консультанты дороги, а ошибки чреваты штрафами. При этом фактические цифры (сальдо ЕНС, обороты, вычеты) уже есть в 1С — но между «законом» и «моими данными» нет мостика.

**Бизнес-метрики (целевые):**
- Сокращение времени подготовки ответа на типовой налоговый вопрос с 30–60 мин до 2–5 мин.
- Снижение числа ошибок в расчётах налогов на 20–30% за счёт сверки с данными 1С.
- 100% ответов ассистента содержат ссылку на статью НК РФ и источник данных 1С (прозрачность).

## What Changes

- Создаётся AI-ассистент по налоговым вопросам: Telegram-бот + RAG-сервис по НК РФ + интеграция с 1С.
- RAG-сервис индексирует НК РФ (актуальная редакция) и находит релевантные статьи по запросу пользователя.
- 1С (на базе каркаса `ai-grd`) предоставляет HTTP-сервисы для фактических данных: сальдо ЕНС, начисления/уплаты, документы, расчёт налога.
- Слой оркестрации (Python/FastAPI) классифицирует запрос, решает, какие источники нужны (RAG / 1С / оба), и синтезирует ответ с цитированием.
- Ассистент работает в Telegram; ответы содержат: текст статьи НК РФ, фактические цифры из 1С, рекомендации.
- Реализуется контур: вопрос → классификация → вызов источников → синтез → ответ с источниками.
- В MVP: 3 налога (НДС, налог на прибыль, УСН), 5 типовых сценариев (ставка, срок, расчёт, проверка сальдо, поиск документа).

## Impact

- **Затронутые capabilities:** `tax-assistant` (новая), `tax-data-1c` (новая), `rag-nk-rf` (новая).
- **Затронутые команды:** бухгалтерия и руководители (пользователи), команда разработки MVP (3 человека: 1С-разработчик, Python-разработчик, бизнес-аналитик).
- **Целевые метрики:**
  - Время ответа на типовой вопрос ≤ 5 мин (включая чтение).
  - Доля ответов с корректной ссылкой на НК РФ ≥ 95%.
  - Доля ответов с актуальными данными 1С (без рассинхронизации) ≥ 99%.
- **Security-профиль:** `baseline: false` — фича работает с **LLM/AI-компонентами** (RAG, tool-calling), **внешним каналом (Telegram)** и **финансовыми данными + PII**. Регуляторика: **152-ФЗ**. Требуется расширенная Threat Model: **STRIDE + OWASP Top 10 for LLM**. Чувствительные данные: финансовые показатели компании, налоговые данные, содержимое запросов пользователей, API-ключи LLM/1С. Обязательна защита от prompt injection, галлюцинаций, утечки данных через Telegram и PII в телеметрии.
- **Operability-профиль:** все 4 столпа наблюдаемости обязательны (logs, metrics, traces, business_signals); корреляция — W3C traceparent; redaction обязателен (PII + financial_data); SLO: p95 ≤ 10с, availability ≥ 99%, error_rate ≤ 1%. Стек: loki (logs), prometheus (metrics), langfuse (traces), otel-collector, grafana (visualization).

## Operability Promise

> Как мы узнаем, что фича работает в production?

- **SLO:**
  - Latency p95 ≤ 10 000 ms (NFR-001)
  - Availability ≥ 99% (NFR-004)
  - Error rate ≤ 1%
- **Ключевые сигналы (инвариант OBS-C-01):**
  - **logs:** `telegram.request.received`, `orchestrator.classified`, `rag.search.completed`, `1c.api.called`, `llm.request.completed`, `answer.sent`, `security.pii.redacted`, `audit.entry`
  - **metrics:** `http.server.request.duration` (RED), `llm.request.duration`, `rag.search.duration`, `1c.api.duration`, `telegram.messages.total`, `answer.citation.present.total`
  - **traces:** span `telegram.message` → `orchestrator.classify` → `rag.search` / `1c.api.call` → `llm.synthesize` → `answer.send`
  - **business signals:** `tax.question.answered` (с `tax.type`, `sources.used`), `citation.present` (bool), `1c.data.freshness`
- **Корреляция (OBS-C-02):** W3C `traceparent` пробрасывается Telegram-бот → Orchestrator → RAG / 1С → LLM (включая async вызовы LLM). `trace_id` присутствует в каждом логе и в `ErrorResponse`.
- **Что НЕ покрыто наблюдаемостью:**
  - Качество RAG-поиска (precision/recall) — измеряется офлайн на эталонных запросах (NFR-002), не в runtime.
  - Корректность налогового совета — вне runtime-наблюдаемости (ответственность пользователя, дисклеймер в ответе).
  - Инфраструктура 1С (ОС, сеть) — вне scope.
  - Внутренние метрики GigaChat API — недоступны.
